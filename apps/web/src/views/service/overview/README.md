# 总览页维护说明

- 页面目录为 `src/views/service/overview/`，菜单路由使用 `/service/overview/index`。
- 本页保留原图 `/Users/fan/Downloads/总览+需求储备库/总览.png` 的布局与信息元素；参考 HTML 为 `/Users/fan/Downloads/总览+需求储备库/总览/index.html`。2026-10-23 的 UI 重构仅调整样式：保留顶部筛选、左侧总览、四张阶段卡片与下方图表/详情的位置，不增删元素，不调整文案、数据与交互。四张阶段卡片内部保持原版的纵向居中排布：图标 → 阶段名称 → 主数值与「占比」标签 → 状态明细，不改成图标与名称横排、数值左对齐的样式（2026-10-26 曾改过一次，已按要求恢复）。视觉以当前组件样式为准，这些约束仅适用于本页。
- 页面使用浅灰工作区、白色卡片、青绿主色、细边框和轻阴影；公共颜色、圆角与阴影变量集中在 `index.vue`。保留电网背景及阶段图标，以遮罩降低背景干扰。数字使用 Arial 与等宽数字特性，单位和说明使用次级文字色；状态明细通过细分隔线与主数值区分。筛选栏与图表区域（含悬浮在图表左上角的排序控件）的输入、切换控件统一为 `32px` 高。
- 仅适配 PC：页面通过 Grid / Flex 撑满父级工作区，不再使用固定画布或整体缩放。页面网格为「筛选栏（`max-content`）/ 汇总区 `minmax(0, 1fr)` / 图表与详情 `minmax(0, 2fr)`」，筛选栏之外的高度按 1 : 2 分给上下两块，两行都以 0 为下限，比例不被内容撑开；页面 `min-height: 700px`，更矮的窗口整体滚动。
- 上方汇总区（总览卡片 + 阶段卡片）随屏幕缩放：`.overview-summary` 是尺寸容器（`container-type: size`），基准字号 = `clamp(12px, min(按卡片宽度换算, 按高度换算), 22px)`，宽度一项取阶段卡片实际宽度（`1 / 13.6`），高度一项按阶段数与最多状态行数折算，保证内容在分到的 1/3 高度内完整放下；卡片内的字号、图标、留白与圆环直径都用 `em` 表示，随基准字号整体缩放。总览卡片与阶段卡片始终一行排布（列模板写在 `--summary-columns`，骨架屏共用），不再在 `1200px` 以下改为两行。汇总区内的文字不省略：数值由 `OverviewValue.vue` 按可用宽度和字数等比缩小，阶段名称、圆心阶段名同样按字数缩小字号。下方图表、表格与筛选栏仍为固定字号。
- 汇总区列宽随屏幕连续变化，不是固定比例：阶段卡片宽度 = `clamp(0px, 15.1cqi, 330px)`（`15.1%` 与原来的 `2.4 : 1` 分栏等价，`1364px` 内容宽度下仍是 `206px`），外部多出来的宽度全部给左侧总览卡片。因此宽屏上四张阶段卡片不会被拉成大片空白，整行保持「一张主卡 + 四张均分卡」的节奏。实测（含顶栏与展开的侧栏）：视口 `1652` → 内容 `1364`，总览 `507` / 阶段 `206`；视口 `1920` → 内容 `1632`，总览 `608` / 阶段 `246`；视口 `2560` 及以上 → 内容封顶 `2240`，总览 `872` / 阶段 `330`。总览卡片拿到额外宽度后内容宽度限制在 `800px` 并居中（`margin-inline: auto`），标题、图例与饼图作为一组保持紧凑，不会出现「文字挤在左边、右边空一大片」；饼图画布仍铺满图例右侧的剩余宽度，圆环画在画布中心，多出来的宽度只增加两侧标签的余量，图例与圆环之间不会空出一段。
- 根据工作区宽度（包含侧栏变化）调整详情：阶段详情默认一行四卡（预算类型占比、项目类型占比、单位/专业排名、项目类型排名，列宽 `0.9fr : 0.9fr : 1.25fr : 1fr`）；宽度不超过 `1200px` 时改为 2 × 2（上排两张圆环、下排两块排名，每行 `300px`），详情区内部滚动。
- 页面宽度自适应工作区，不再有 `1440px` 这类小上限：`.overview-viewport` 铺满工作区、负责滚动与浅灰底色，`.overview-page` 为 `width: 100%`，`1652px` 内容宽度下就是满宽显示，只有工作区超过 `2240px`（4K / 带鱼屏）时才收敛到 `2240px` 并居中（`margin-inline: auto`），避免一行拉到几千像素反而看不清；两侧留白沿用工作区同色 `#f3f6f8`。页面自身即命名宽度容器 `overview`（`inline-size`，仅宽度查询），筛选栏、阶段详情的宽度断点量到的是实际内容宽度。页面不设内边距（`.overview-page` 为 `padding: 0`），区块间距随屏幕轻微放大（`--overview-gap: clamp(8px, 0.5vw, 12px)`，`1920` 视口约 `10px`、`2560` 视口 `12px`），大屏上卡片变大时间距同步变大，不会显得挤在一起；共享布局 `.rr-view-ctx` 的 `10px` 内边距保持不变。

## 分层与数据流

本目录承载两个路由页面：`index.vue`（总览，组件名 `/service/overview/index`）与 `config.vue`（阶段配置，组件名 `/service/overview/config`，由菜单下发）。两者只共享 `types.ts` 与样式，查询逻辑互不相干。

代码按三层组织，数据只沿一个方向流动：

1. **状态**：`index.vue` 持有筛选条件、数据维度与阶段选中态，弹窗目标（`drillTarget` / `detailTarget`）也在这里统一管理；子组件通过 props 读取、通过事件回报，不回写父级状态。
2. **纯函数**（`data/*.ts`）：阶段与公共代码解析、请求参数、排序、金额/占比格式化、平铺行、分页、配置表单。这一层无副作用、不依赖 Vue 与浏览器，可直接用 Node 跑单测（`tests/overview*.test.cjs`）。
3. **取数与状态机**（`composables/*.ts`）：`useAsyncTask` 统一 `data` / `loading` / `error` 与在途请求作废，`useStageDetail` / `useStageWideTable` / `useOverviewChart` 在其上组合具体接口与 ECharts 生命周期。组件里不再手写请求号与 `try/finally`。

所有 `/xmzl` 请求的公共参数只由 `data/query.ts` 生成：`buildOverviewBaseParams`（角色上下文 + `jhssnd` + `nd`/`yd` + `chooseYjdws`/`chooseZybms` + `searchBy`）→ 需要组织类型时套 `withOrgSearchType`（仅按单位）→ 需要阶段时套 `withStage`；接口各自的字段（`orderBy`、`yslx`、`xmlxId`、`searchZybm`、`page`/`limit`）由调用方追加。新增接口时按这三步组合，不要再手写一份参数对象，否则「全页同口径」就只是口头约定。

- 图表仅在对应图表视图可见且有数据时创建；切换至表格、空态或卸载时销毁实例，返回图表时重新创建。
- 图表通过 `ResizeObserver` 监听自身容器尺寸，随工作区、侧栏和卡片重排同步更新，柱宽与图例位置不依赖固定画布；同帧多次触发时用 `requestAnimationFrame` 合并为一次 `resize`，拖拽分栏期间不会反复同步布局。
- 各区域样式保留在组件的 `scoped` 样式中；详情共用样式也在组件内引入，避免影响其他页面。唯一例外是统计月份面板：Element Plus 把它挂在 `body` 下，scoped 样式够不到，`OverviewFilters.vue` 里单独一段非 scoped 样式只按 `popper-class="overview-month-popper"` 生效。
- 汇总区外层是尺寸容器（`container-type: size`），高度完全由页面网格分配，不受卡片内容撑开；卡片网格撑满这块高度，退出过渡的旧内容绝对定位重叠。不要再在外层套隐式 Grid 来叠放过渡节点，否则嵌套 `min-content` 会反复测量卡片，金额/数量切换及图表尺寸读取都会触发昂贵的同步布局。
- 汇总区样式里的 `min()` / `max()` / `clamp()` 含 `var()` 时要写成 `~'...'` 原样输出：Less 4 会在编译期计算这些函数和括号内的运算，遇到 `var()` 直接报 `Operation on an invalid type`。
- 样式性能约束（实测记录，改动前请先读）：
  - 盒模型 reset 只写一份，在 `index.vue` 的非 scoped 样式里用 `.overview-page *` 收敛（原先是 8 处、共 23 条选择器，各自只覆盖自己子树）。scoped 样式里的 `*` 会被编译成 `*[data-v-x]`、只在本组件子树生效，所以每个组件各写一份时并不会互相覆盖，而是全部叠加参与匹配；`.overview-page` 前缀（一个类）与原来的 `[data-v-x]`（一个属性）优先级相同，层叠顺序也不变。不要再往组件或 `styles/*.less` 里加第二份 reset。
  - 页面内没有 `transition: all`、没有 `backdrop-filter` / `filter: blur`、没有悬停改布局（padding / border-width / width）的规则，四类典型卡顿来源目前都是 0，新增样式请保持。
  - 触发 layout 的过渡只有三处，且都只在用户操作时运行：筛选栏展开的 `grid-template-columns`（0fr → 1fr，280ms）、「数据更新时间」的 `max-width`（240ms）、分隔线的 `width`（240ms）。不要把这些过渡挂到滚动或 `ResizeObserver` 驱动的持续路径上。
  - 滚动与悬停只做 paint：表格斑马纹、行悬停底色、卡片阴影与描边，均不改变盒模型。
  - 骨架屏动画只动 `opacity`，且页面不可见时由 `useDocumentVisibility` 暂停（`.is-paused`），不要改成 `background-position` / `height` 之类的重绘或重排动画。
  - 已知冗余（评估后保留）：`styles/filter-field.less`（3551 B / 1134 B gz）被 3 个组件 scoped 引入、`switch.less` 与 `detail-card.less` 各被 2 个，重复约 10 KB raw / 3.4 KB gz。要消除重复只能改成非 scoped 共享样式，但 `.filter-label`、`.filter-value` 这类类名一旦全局化就有跨页面污染风险；3.4 KB 的收益不值得换来这个长期隐患，故保持现状。
  - 真正的运行期成本在容器查询：汇总区用 `cqi` / `cqh` 推导基准字号、`OverviewValue` 按自身宽度换算字号，窗口拖动时整个汇总子树会重算字号并重排。这是「文字永远完整显示、不省略」这一视觉要求的代价，不是疏漏；只有愿意接受省略号或固定字号时才能拿掉。
